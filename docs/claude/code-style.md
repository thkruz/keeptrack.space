# Code style rules agents get wrong

`pnpm run lint` (Biome) and `pnpm run typecheck` catch most formatting and type problems. The
rules below are the ones that slip past them or that agents repeatedly break anyway.

## TypeScript

- **Every regular expression needs the `u` flag** (or `v`): source, tests, locale patterns and
  generated code. `/\s+/gu`, `{ hasText: /^Planets$/u }`. A Biome plugin
  (`biome-plugins/require-unicode-regexp.grit`) warns about it; treat the warning as an error.
- **LF line endings only.** Agents on Windows sometimes write CRLF; check before committing.
- Private class members end in an underscore: `rewindBtn_`, `stopRewind_()`.
- Avoid `== null`. Use `typeof value !== 'number'` for optional numbers, or a strict
  `=== null` / `=== undefined`.
- Cache `ServiceLocator.getXxx()` results in a local at the start of a method instead of
  calling the locator repeatedly.
- Pull complex conditional UI updates into small named helpers (`updateButtonForPaused_()`)
  instead of growing one handler.
- Never build HTML from strings that contain user input, URL parameters, saved settings or
  catalog text. Create elements and set `textContent`, `value` and `dataset`; code scanning
  flags `innerHTML` built from such strings.
- Don't use `Math.random()` for ids or anything that looks security-related; a counter is
  enough for unique DOM ids and does not trip the scanners.

## Translations

- User-facing text goes through `t7e()` with a key that exists in `src/locales/keys.ts`.
  Keys are generated by `pnpm run generate-t7e`; never reference a key that is not there.
- Plugin locale files are `locales/<lang>.src.json`, one per supported language (see
  `SUPPORTED_LOCALES` in `src/locales/locales.ts`), with strings wrapped in `"plugins"`. Add
  the key to every language, not only English.
- **Arrays of filters or options need explicit ids.** Never derive an id from a translated
  name; it changes with the language.
- **Use static getters for translated arrays:**
  `static get filters() { return [{ id: 'x', name: t7e('key') }]; }`, not
  `static filters = [...]`, which runs before translations load. Getters return fresh
  objects, so don't mutate the result and expect it to stick.

## Settings

- Plugin settings need a type assertion:
  `(settingsManager.plugins?.[this.id] as { myOption?: number })?.myOption`.
- **A new property on a settings class (for example `CameraSettings`) needs an entry in
  `PROPERTY_CATEGORY_MAP` in `src/settings/settings.ts`.** Without it,
  `settingsManager.newProp` is silently `undefined`, which turns into `NaN` in math code.

## UI

- Side menus use the v13 card layout from `src/engine/ui/menu-v13.css`: add `kt-ui-v13` to the
  menu root and build with `kt-*` blocks. Use `src/plugins/catalog-management/` as the
  reference.
- Use `<div class="kt-section-label">` for section headings, not a centred `<h5>`.
- Call `initMaterialSelects(menuRoot)` when the menu has select elements.
- Form ids follow `<elementName>-form`. After renaming a DOM id, search for every reference.
- Secondary menus such as result tables stay open after an interaction; the user closes them.
- To jump the simulation to a time, call `timeManager.changeSimulationTime(targetMs)`. Don't
  use `changeStaticOffset(targetMs - Date.now())`: it reads the wall clock twice and leaves a
  paused clock off by a millisecond. Jumps keep the current play or pause state.
- Every new control must work on a phone-sized viewport (about 390 by 844) as well as a laptop.

### v13 side-menu checklist

A menu that works and passes its tests can still look out of place. Before opening a pull
request, compare yours with `src/plugins/collisions/` and `src/plugins/reentries/`.

- `getSideMenuConfig()` returns `dragOptions: this.getDragOptions_()` with
  `{ isDraggable: true, minWidth: 400, maxWidth: 550 }`, so the menu can be resized. See
  `src/plugins/catalog-management/` for the call.
- Action buttons (`kt-action`) such as Refresh go in a `<section class="kt-section">` headed by
  `<div class="kt-section-label">Data Actions</div>`. Status text belongs in that section too,
  not loose above the tabs.
- The data goes in its own `kt-section` headed "Results". Cards inside it get a
  `kt-section-label` too.
- Section labels are `<div class="kt-section-label">`, never `<h5>`.
- For shared labels such as Results and Data Actions, reuse the translation keys another
  plugin already has. The wording then matches in every language and you add no new strings.
- Before writing a lookup or formatter, search `src/app/data` and `src/engine/utils` for an
  existing helper (for example `getHostLabel()` in `src/app/data/station-modules.ts`).
- When ranking rows, compare each row with the one before it. Don't call `findIndex` over the
  whole list: it is only right when the server sorts ties next to each other, and it is O(n^2).
